# 权限守卫架构说明

## 概述

系统采用两层权限守卫，分别在前端和后端拦截非法访问。两层守卫保护的**资源类型不同**，但判断依据是同一套权限码，数据源都是登录时写入的 Cookie。

## 守卫资源对照

| 层级 | 运行位置 | 守卫对象 | 资源举例 | 没权限的后果 |
|---|---|---|---|---|
| 前端路由守卫 | 浏览器 | 页面路由 | `/agents`、`/admin` | 看不到页面，跳转 403 |
| 后端路由守卫 | 服务器 | API 接口 | `POST /auth/login`、`GET /publish/agents` | 接口返回 403，拿不到数据 |

## 拦截流程示例

### 示例 1：用户点击"智能体列表"菜单

```
用户点击"智能体列表"
  │
  ├─ ① 前端路由守卫（浏览器执行）
  │     读 Cookie 中的权限码
  │     检查是否有 agent:view 权限
  │     ├─ 有权限 → 渲染页面，继续下一步
  │     └─ 无权限 → 拦截，跳转 403 页面，流程结束
  │
  └─ ② 后端路由守卫（服务器执行）
        前端调用 GET /publish/agents
        读 Cookie 中的权限码
        检查是否有 agent:view 权限
        ├─ 有权限 → 返回智能体列表数据
        └─ 无权限 → 返回 HTTP 403，前端收到错误提示
```

### 示例 2：用户直接在浏览器地址栏输入 URL 绕过前端

```
用户在地址栏直接输入 /admin
  │
  ├─ ① 前端路由守卫
  │     React Router 匹配到 /admin 路由
  │     守卫组件检查权限
  │     ├─ 有权限 → 渲染页面
  │     └─ 无权限 → 拦截，跳转 403 页面
  │
  └─ ② 即使前端守卫被技术手段绕过
        前端仍需调用后端接口获取数据
        后端守卫检查 Cookie 中的权限码
        └─ 无权限 → 返回 403，页面无数据可用
```

## 两层守卫的关系

```
┌─────────────────────────────────┐
│          前端（浏览器）           │
│                                 │
│  路由守卫 → 权限码校验 → 页面渲染  │  第一道防线（体验层）
│                                 │
│  权限数据来源：Cookie             │
└────────────────┬────────────────┘
                 │ 调用 API
                 ▼
┌─────────────────────────────────┐
│          后端（服务器）           │
│                                 │
│  装饰器/依赖工厂 → 权限码校验     │  第二道防线（安全层）
│                                 │
│  权限数据来源：Cookie             │
└─────────────────────────────────┘
```

- **前端守卫**：提升用户体验，没权限的页面直接不展示
- **后端守卫**：安全兜底，即使前端被绕过，数据也不会泄露
